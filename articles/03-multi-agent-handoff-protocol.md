# 65 个仓库、6 家 AI agent 轮换开发不失忆：我的交接协议

> 我用 Claude Code / Codex / Cursor / Gemini / Windsurf / Kimi 轮换开发 65 个仓库。这套工作方式最大的敌人不是代码质量，是**失忆**。

## 问题：agent 的记忆止于会话

同时用多家 AI agent 的人都有这个体验：今天下午 Claude 帮你把架构理顺了，明天早上你换 Codex 接着干，它对昨天的一切一无所知——于是一个上午就在"重新探索"和"重复犯错"中烧掉。

我历史上最大的错漏来源甚至不是代码 bug：2026 年 7 月我做了一次目录重组，之后说明书里手写的 8 个项目路径全部失效。后续的 agent 按旧路径扑空、猜错、改错仓库——**文档里过时的信息比没有信息更害人**。

教训很清晰：**上下文只能靠仓库里的文件传递，不能靠对话记忆，也不能靠任何一家厂商的私有记忆功能。**

## 方案：把理解固化进仓库的四个文件

```
AGENTS.md        唯一权威协作守则（所有厂商的 agent 一视同仁）
docs/HANDOFF.md  交接状态板：当前目标/已完成/进行中(含文件行号)/已知坑/下一步/验证方式
docs/adr/        架构决策记录，治"忘了为什么这么改"
CLAUDE.md 等     全部只是指向 AGENTS.md 的指针，冲突时以 AGENTS.md 为准
```

配套两个纪律：

**开工前三步**（任何 agent 进任何仓库必做）：
1. 按固定顺序读：`README* → AGENTS.md → docs/HANDOFF.md → docs/adr/ → git log -10`
2. 先跑一次仓库里写的验证命令确认基线是绿的——**基线红就先修基线，绝不在红基线上叠改动**
3. 用自己的话复述当前任务与验收标准，对齐 HANDOFF 后再动手

**收工三件套**：跑完整验证全绿 → 更新 HANDOFF.md → 提交 git，不留未提交的半成品。

## 关键设计决策（都是踩坑踩出来的）

**为什么不用 `.claude/`、`.cursor/` 这些厂商私有目录存交接信息？** 这是失忆的头号原因——写进 Claude 私有目录的上下文，换 Codex 就失明了。交接文件必须放在仓库的厂商中立位置。

**为什么需要机械护栏？** 自觉是最不可靠的关卡。我在 65 个仓库装了 pre-push 钩子：改了代码但没更新 `docs/HANDOFF.md` 的推送会被拦下。确有正当理由可以 `--no-verify` 跳过，但你必须亲口说出理由。

**为什么 ADR 是强制项？** 因为"对话里想通但没落盘的决策，等于没发生过"。三个月后——或者换个 agent——没人知道当初为什么这么改，于是改回去再踩一遍坑。

**为什么任务粒度是"半天能讲完"？** 因为交接失败的头号原因就是粒度过大。一个任务一个分支，每次收工留下可接续的状态——半成品 + 清晰交接，远好过藏着不说。

## 效果

协议落地后，换 agent 的接续成本从"一上午重新探索"变成"读完 HANDOFF 直接动手"；pre-push 钩子每周拦下一两次"忘了更新交接"的推送；7 月目录重组那种路径集体失效的事故再没有复发——因为权威路径表改成由磁盘现状自动生成了。

## 自己部署一套

整套架构（模板 + 幂等部署脚本 + 踩坑记录）开源在：

- 仓库：https://github.com/iPythoning/VibeDevOps-skill
- 一键部署（先 `--dry-run` 看清单，只新增不覆盖）：`skills/vibedevops/scripts/deploy-handoff.sh`
- 不确定自己的项目缺什么？先跑 30 秒体检拿缺口清单：

```bash
curl -fsSL https://raw.githubusercontent.com/iPythoning/VibeDevOps-skill/main/skills/vibedevops/scripts/health-check.sh | bash -s -- /path/to/your/repo
```

AI 编程的速度可以全拿，但理解不能全丢——理解不是看懂每一行代码，而是任何时候都能回答四个问题：改了什么、为什么改、动了哪里、怎么验证。
