# ADR 0002：合并 main 即授权自动部署

- 状态：已接受
- 日期：2026-08-10
- 决策者：用户 / Codex

## 背景

旧规则同时要求“PR CI 全绿后合并”与“合并后再次人工批准生产部署”。第二道审批让已合并版本停留在不可见队列，造成 main 与生产长期漂移，也破坏持续部署的确定性。

## 决策

PR 审核与合并是生产发布的唯一人工授权边界。PR 合并进 `main` 后，CD 重验合并结果，只构建一次以 SHA/digest 标识且带 provenance/SBOM 的不可变制品，再用 OIDC 短期身份渐进部署。功能层 smoke/canary 或真实指标失败时自动推广上一绿制品并复验。`workflow_dispatch` 只用于重试、回滚和事故恢复，不作为正常发布必经路径。需要等待发布时间窗口时延迟合并。

## 备选方案

- 合并后 GitHub Environment 人工 approve：重复授权，容易形成无人处理的发布队列。
- 仅手动 `workflow_dispatch`：main 与生产状态无法保持一致，持续部署退化为手工发布。

## 后果

main 与生产保持可预测的一致性，制品来源可验证，失败通过自动回滚止损。代价是 PR 阶段的测试、审核、发布窗口判断，以及 CD 的指标门、部署身份和回滚能力必须可靠，不能把风险推迟到合并后处理。
