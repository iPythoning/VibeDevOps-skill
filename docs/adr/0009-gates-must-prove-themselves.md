# ADR 0009：门禁必须自证有效，验证路径必须与生产同形

- 状态：Accepted
- 日期：2026-08-19
- 补充：ADR 0002（合并即部署授权）、0006（变量路由）、0008（出境链路实测）

## 背景

一条 CI/CD 链路被反复「修好」了一周，每次都有绿色证据，而真实的
`push → 生产` 从来没有走通过一次。复盘时发现，**三道独立的门禁在同一天被证明是假的**，
而且形状完全一样：**验证时走的那条路，和生产实际走的那条路，不是同一条。**

| 门禁 | 「验过了」验的是什么 | 真相 |
|---|---|---|
| CD 全链 | 手工触发构建工作流（此时仓库 secrets 可用） | 生产经**可复用工作流调用**进来，secrets **全是空字符串** |
| 依赖瘦身 | 在**仍装着该依赖**的镜像上跑导入冒烟 | 真正卸掉它的镜像从未被验证 → 上线即崩 |
| 密钥扫描 | 「它一直是红的，已知问题」 | 红的原因是扫描器**自身**调用外部 API 失败，**一次密钥都没扫过** |

三者都不是「粗心」，而是**同一个结构性缺陷**：绿色/红色信号与它声称代表的事实之间，
没有任何机制保证对应关系。

## 决策

### 一、门禁必须能证明自己会失败（金丝雀）

**一道从未失败过的门禁，和一道不存在的门禁，在证据上无法区分。**

因此：**任何拦截型门禁，必须在每次运行时先证明自己有效，再去做真正的检查。**

密钥扫描的实现方式：在临时目录里现造一个**随机生成**的假凭据，先让扫描器扫它——
扫不出来就让这一步失败，并明说「本次『扫描通过』不可信」。随机生成是刻意的：
写死的样本会进仓库、会被下一步自己扫到，也会随时间变成真的可疑内容。

同理适用于：Lint 规则、类型检查、安全策略、健康检查、回滚逻辑。
**回滚路径必须在平时就被走过一次**——不能等出事时第一次用。

### 二、跳过不是通过

守卫写成 job 级 `if:` 条件时，不满足条件的行为是**跳过**，而**跳过的工作流在界面上是绿的**。
于是「拒绝部署」和「部署成功」长得一模一样。

**因此：拦截必须是显式失败（非零退出 + `::error::`），不能是条件跳过。**
守卫放在第一个 job 的第一步，或独立成一个前置 job，让下游 `needs:` 自然阻断。

### 三、验证入口必须与生产同形，多余的岔路要删掉

**规矩不如机制。** 与其规定「测试要走生产同款路径」，不如**把不同形状的入口删掉**：

- 构建工作流只保留「被部署工作流调用」这一种触发方式，删掉手工触发；
- 手工部署入口保留在部署工作流上（它经同一条调用链），但**必须加分支守卫**——
  手工触发默认可对任意分支生效，不拦就等于「任意分支可部署到生产」。

代价要说清楚：删掉手工构建后，就不能「只构建不部署」。补偿方式是**把「构建但不推送」
加进 PR 门禁**——它与生产同形，不会造出第二条假路。

### 四、可复用工作流不会继承 secrets

调用可复用工作流时，**除平台自动提供的令牌外，仓库 secrets 不会自动传入**，
必须在调用处显式声明继承。缺了它，被调用方拿到的是**空字符串而不是报错**——
再叠加 `set -e` 与被重定向掉的 stderr，表现为**整步零输出、退出码 1**。

**因此：所有必需的 secret 必须在使用前显式断言非空**（`: "${VAR:?...}"`），
把「配置缺失」变成一条能读懂的错误，而不是一次沉默的失败。

### 五、禁止吞掉 stderr

`cmd 2>/dev/null` 配合 `set -e`，会把「为什么失败」连同失败一起吞掉。
本次事故中，一条被重定向的主机密钥扫描命令，让整个部署步骤零输出退出。

**规则：门禁与部署脚本中不得重定向 stderr 到 `/dev/null`。**
需要静音的只有已知无害的噪声，且必须单独注释说明。

### 六、删除依赖必须在真正没有它的产物上验证

一个依赖被改成可选之后，代码里的 `try: import X except ImportError: X = None` 守卫
**只挡得住运行时使用，挡不住导入期求值**——例如函数签名里的类型注解会在类定义时求值，
`None.Attr` 直接抛异常，应用启动即崩。

**因此：删依赖后的验证必须在「真正卸掉该依赖的产物」上进行，且要复现应用的完整启动链，
而不是跑一遍 `import`。** 在仍装着该依赖的镜像上做的验证，等于没做。

### 七、配置存在 ≠ 消费方读了它

同一天内三次踩到：变量设好了，但工作流没有读它；文件改好了，但生成它的脚本没改。

**排查口诀：配置存在 ≠ 消费方读了 ≠ 消费方认。三处都要对上。**
修复必须落在**生成方**；只改产物等于未修复。

### 八、多写入者环境的动手纪律

多个自动化会话共享同一批仓库时：
- **创建分支前先查远端是否已有同名分支**，以及本地是否有工作树占用它；
- 发现他人已在解同一个问题时，**在其分支上追加，而不是另开一条**；
- 推送必须显示错误。静默推送失败与推送成功在终端上无法区分。

## 结果

- 门禁上线的验收标准从「它绿了」改为「**它证明过自己会红**」。
- 拦截一律显式失败；`if:` 跳过不得用作安全控制。
- 与生产不同形状的验证入口，删除而非规范。
- 所有必需 secret 前置断言；脚本不得吞 stderr。
- 依赖变更在「真正没有它」的产物上验完整启动。
