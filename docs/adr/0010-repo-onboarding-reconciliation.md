# ADR 0010：仓库接入自治——「记得跑」不是机制，对账收敛才是

- 状态：Accepted
- 日期：2026-08-22
- 关联：ADR 0006（变量路由）、ADR 0007（failover 自治）、ADR 0009（门禁自证）

## 背景：新仓必撞额度死，且 failover 救不了它

托管 CI 账单/额度死透（不再续费）之后，存量仓靠 ADR 0006/0007 的变量路由 +
自动 failover 稳定运行在自建 runner 车道。但**每一个新建仓库仍然必撞「额度不足」
0 步失败**，反复发生。根因链：

1. 模板 workflow 的路由 fallback 是 hosted（`vars.CI_RUNNER || 'ubuntu-latest'`）——
   变量没人设，就跑 hosted，就撞账单。
2. ADR 0007 failover 的无人值守安全阀是「runner 不在线不切」——**没注册 runner 的仓
   是 failover 的盲区**，它无处可切，永远红。
3. 「建仓后记得跑接入命令」是流程上的无主步骤：人和 agent 都会忘，而且仓库可以从
   任何入口创建（CLI、网页、另一台机器、另一个 agent），事件钩子拦不全。

一次实弹修复（某客户站仓库 deploy 连续多次 0 步失败）确认了完整病灶：变量缺 +
runner 缺 + workflow 写死 hosted 标签，三处都要补，且没有任何机制保证下一个新仓不再犯。

## 决策

**接入从「事件驱动」改成「状态收敛」**：在构建机上跑一个 root 对账循环
（`onboard-reconcile`，systemd timer，30 分钟一轮），期望状态定义为——

> OWNER 名下每一个「有 `.github/workflows` 的非归档非 fork 仓」，
> 都有本构建机的 runner（平台侧 online）且路由/构建变量齐全。

每轮对账把现实收敛到期望状态。即时通道（`onboard-repo.sh <owner/repo>`）是同一份
实现的单仓模式 wrapper——**两个入口一份逻辑，永不漂移**。

### 纪律（每条都有当日实战事故背书）

1. **只做加法**：注册缺失的 runner、补缺失的变量；**绝不覆盖已存在的变量值**。
   某些仓刻意配置了不同车道（如 mac 构建），对账夷平它们等于制造新事故。
2. **「已注册」以平台侧 API 为准，不信本地目录**。`config.sh` 断链会留下半配置
   残留——新版 runner 的配置文件是 `.runner_migrated` 而不是文档里的 `.runner`，
   只按后者判断/清理会陷入「already configured」死循环。清理清单必须是
   `.runner*` `.credentials*` `.env` `.path` 全集。
3. **注册失败整目录删除重来**——半配置残留会毒化下一轮对账。
4. **注册是单写入者**。两条注册通道（窗口循环 + 逃生 job）并发跑同一仓时，
   后到的 `--replace` 会吊销先到者刚拿到的凭据，互相毒杀；一次只开一条通道。
5. **全程构建机本机完成，不依赖入站通道**。注册 runner 本来就是本机操作；
   对账循环跑在构建机自己身上，overlay 网络入站挂死一整天（实测：出站健康、
   DERP pong 通、TCP 22 死）也不影响新仓接入。
6. **新 runner 单元必须出厂即带出网配置**（代理 drop-in 等）——否则从注册到
   网络自适应层下一轮补配之间存在「裸奔空窗」，首个 job 的包管理器直连超时
   （实测：npm prebuild 下载 140 秒卡死）。修复落在单元生成器，不是事后补。
7. **token 只进请求头**，不进日志、不进 argv；密钥盘 600 存放，轮换一条命令。
8. **退出通道**：不想被接入的仓写进 skip 清单（版本化文件），对账跳过。

### 天花板（诚实记录）

- 逃生通道（用某仓已 online 的 runner 跑 job 代办另一仓的注册）受
  **无特权天花板**限制：runner 用户装不了 systemd 单元，注册完成后单元要等
  root 侧生成器跑一次。它是「控制通道挂死时把 90% 准备工作做完」的手段，
  不是完整替代。
- 对账粒度是「有 workflow 的仓」。极端情况下（数百个带 CI 的仓）会注册出
  数百个常驻 Listener；当前量级（几十个仓、每 Listener ~100MB、构建机内存
  数十 GB）远未到需要收紧的程度。若到了，把判据收紧为「近 N 天有 push」。

## 后果

- 首轮全量对账即清账：35 个存量仓自动注册 runner、补齐 367 个变量，一个
  历史挂起的「只差注册」待办被顺带自动关闭——这正是对账模式对事件模式的优势：
  它不区分「新欠的」和「旧欠的」。
- 新仓从「必撞额度死」变成「最迟 30 分钟自动接入；想立即接就跑一条命令；
  忘了也没事」。
- 与 ADR 0007 组合后，自建车道的两个盲区（没注册的仓、注册了但配置漂移的仓）
  全部关闭：0007 管「已接入仓的故障切换」，0010 管「让所有仓都处于已接入态」。
