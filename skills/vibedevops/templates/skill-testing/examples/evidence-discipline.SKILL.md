# 证据纪律

**观测到 X 就断言 Y，而没有先确认「这个观测手段在非 Y 的情况下会给出不同结果」——
这是本机历史上最高频的失败模式**（记忆库 59 条教训里 13 条属此类，是第二名的三倍；
且多条明确记着「第二次」「同型」）。

它不挑领域：排查生产故障、验证部署、判断门禁有效性、确认数据是否丢失，全都中招过。
共同点是**观测本身出了问题，而结论看起来很确定**。

## 三个动作（下确定结论前必做）

### 1. 反向自证：这个观测在「另一种情况」下会不同吗？

问自己：**如果事实是相反的，我这条命令的输出会变吗？**

不会变 → 这条观测没有信息量，换一个。

- 判断门禁是否真在拦 → 先造一个**必然违规**的输入，确认它真的红
- 判断扫描器是否有效 → 先扫一个**随机生成**的假凭据，确认它真的报
- 判断回滚是否可用 → **平时就走一次**，不要等出事时第一次用

这是 ADR 0009「门禁必须自证有效」的泛化——从门禁泛化到一切观测。

### 2. 穷举解释：这个结果有几种可能的原因？

看到某个观测结果时，列出**所有**能产生它的原因，而不是最顺手的那个。

| 观测 | 顺手的解释 | 同样能产生它的其他原因 |
|---|---|---|
| `curl` 返回 000 / 连接失败 | 服务挂了 | 本机 hosts 劫持、TUN/代理拦截、DNS 污染、防火墙 |
| 统计表 0 行 | 功能没人用 | writer 链路断了、查错了库、租户隔离过滤掉了 |
| `git log` 看不到提交 | 对方没提交 | 本地没 fetch、看错分支、提交在别的 remote |
| 某张表查不到记录 | 这件事没发生 | **字段在另一张表上**、查询条件写错、软删除 |
| 命令退出码 0 | 成功了 | 管道吞了真实退出码、命令是 no-op、错误走了 stdout |
| 日志里没有报错 | 没出错 | 日志级别过滤掉了、错误被 try/except 吞了、写到别的文件 |
| 页面 HTTP 200 | 页面正常 | JS 运行时报错、资源 404、渲染空白、首屏 5 秒 |

**只有当其他解释都被独立排除，才能下确定结论。**

### 3. 第二通道：换一条独立路径复核

关键结论必须有**两条不共享失败模式**的证据支持。

- 本机 `curl` 不通 → 换**第三方节点**测（本机代理/hosts 是共享失败模式）
- 数据库查不到 → 换**另一张相关表**或应用日志交叉验证
- 门禁绿 → 加一条**实际操作产品**的证据（门禁与产品是两条通道）
- 一台机器上够不着 → 从**第三台**测，别在同一台上反复重试

## 高频陷阱（都真实踩过，各自有事故背书）

- **管道吞退出码**：`cmd | tail` 之后的 `$?` 是 `tail` 的。判断成败要么不接管道，
  要么用 `PIPESTATUS`，要么把退出码单独捕获
- **错误走 stdout**：某些 CLI 在 404/失败时把错误 JSON 打到 **stdout** 而非 stderr，
  于是「输出为空即失败」这类判据永远为假
- **jq 的 `//` 把 false 当空**：`.field // empty` 在 `field=false` 时返回 empty——
  布尔字段不能这么取
- **`--if-present` 类开关**：脚本不存在时静默成功，**跳过被当成通过**
- **订阅时机**：调试协议只推送订阅**之后**的事件，先导航再监听会漏掉首屏的全部错误
- **健康检查窗口太短**：包含数据库迁移的发布，60 秒窗口内还没起来，会误判成失败
- **看似执行实为 no-op**：如 `compose up --build` 对只有 `image:` 没有 `build:` 的服务
- **观测环境污染**：本机代理会给证据混进 `ERR_TUNNEL_CONNECTION_FAILED` 之类的
  假错误，判断前先在无代理环境复测

## 什么时候**不适用**（同样重要）

本 skill 只在「**要从观测推断出一个判断性结论**」时生效。以下场合不适用，
套用它是纯粹的成本：

- **执行明确指令**：列目录、读文件、改个错别字、按给定路径创建文件——
  任务本身没有要你判断什么，做完即可
- **结论由任务自带**：用户已经告诉你事实，你只是执行
- **单向可逆低代价**：跑一次单测、看一眼日志、查个函数签名

判据很简单：**问自己「我最后要下一个可能错的判断吗？」**
不需要下判断 → 不适用。

（首轮评测实测到的滥触发：一个「列出某目录下有哪些文件」的任务，
被全程套用了三步法——那里没有任何需要推断的事实。）

## 需要下判断时，严格程度按代价定

代价与不可逆性决定走几步：读一眼日志给自己看，走第一步就够；
要据此改生产、删数据、给用户下结论、或者判定「某件事没发生过」——三步都要走。

## 反模式

- 「我查了表，没有记录，所以没发生过」——除非你确认了字段就在这张表上
- 「CI 绿了，所以能上线」——CI 覆盖不到的部分谁看的？
- 「重试了三次都不行，肯定是对方挂了」——三次都走同一条链路，等于一次
- 「日志里没有，所以没执行」——先确认那条路径真的会写日志
